# API specification
Updated 2026-10-22. Actual routes below are distinct from proposed full-platform APIs.

## Synthetic demo at 127.0.0.1:8120
Next.js on 127.0.0.1:3006 proxies /api requests here. DAPPER_DEMO=1 is mandatory. Except health and the demo-session route, a random shared HttpOnly SameSiteStrict demo cookie is required. This is not production authentication.

| Method | /api/v1 route | Behavior |
| --- | --- | --- |
| GET | /health | Local demo health and productionReady=false |
| GET | /demo/session | Establish synthetic shared demo cookie; no real identity |
| GET | /workspace | Synthetic customers, vehicles, appointments and public location facts |
| POST | /customers | Validate, reject duplicate demo email, persist locally |
| POST | /vehicles | Validate owner, inherit location, reject duplicate owner identifier, persist locally |
| GET | /catalogue/reference | Ten public website page references |
| GET | /catalogue/bookingpress | 79 source service / 12 category references with provenance and review flags |

Demo writes require Origin http://127.0.0.1:3006, strict bounded JSON and loopback Host. Error codes include 400 malformed/unknown fields, 401 no session, 403 origin/Host, 409 duplicate demo records, 422 field errors and 500 persistence failure. Failed writes roll back in-memory append state. Prices and durations are not approved transaction values.

## Scoped PostgreSQL foundation at loopback 8121
The opt-in cmd/workspace server requires DAPPER_WORKSPACE=1 and a privately supplied DAPPER_DATABASE_URL. It is not connected to the demo frontend. Health explicitly reports productionReady=false and identityProviderConfigured=false. No login, password, principal provisioning or session-issuance route exists.

| Method | /api/v1 route | Boundary |
| --- | --- | --- |
| GET | /health | Loopback Host; no bearer required |
| GET | /auth/me | Active, unexpired, unrevoked PostgreSQL bearer session |
| POST | /auth/logout | Same-origin write; revoke current session |
| GET/POST | /organizations/{organization}/locations/{location}/customers | Session actor plus matching customer read/create grant |
| GET/POST | /organizations/{organization}/locations/{location}/vehicles | Session actor plus matching vehicle read/create grant and customer ownership |

Organization/location IDs in paths are selectors, never authority. Actor identity comes only from the validated session. Actor/scope injection in JSON is rejected. Lists are currently bounded to 100 records; full pagination/search is unfinished. Responses use no-store. Database errors are not returned to clients.

Customer body: name, email, phone. Name is validated; provided emails/phone values are checked without imposing an approved booking contact policy. Vehicle body: customerId, description, categoryDescription, identifier. Responses use camelCase JSON. Same-origin writes and application/json are required; strict bodies are bounded to 8192 bytes. Typical statuses: 400 invalid payload/selector, 401 invalid session, 403 missing grant/origin/Host, 415 content type, 422 fields or scoped customer link, 503 service failure.

Tests execute these handlers against real PostgreSQL synthetic schemas, including persisted writes, negative scope/grant access and logout. This is local handler/database evidence, not a live identity-provider or production deployment claim.

## Production Booking, Invoicing, Calendar, and SOP APIs — 2026-10-22
Deployed on migrations 22, 23, and 24:

1. **Bookings API (`/bookings`)**:
   - `GET /organizations/{org}/locations/{loc}/bookings` — requires `bookings.read`. Query params: `from`, `to`, `status`, `limit`.
   - `POST same /bookings` — requires `bookings.create`. Body: `customerId`, `serviceId`, `addonIds`, `reservationId`, `channel` ('online', 'internal', 'phone', 'walk_in', 'dealership'), `status` ('pending', 'confirmed', etc.), `bookingTime`, `notes`.
   - `GET same /bookings/{bookingId}` — requires `bookings.read`. Returns booking entity and full `booking_events` audit trail.
   - `POST same /bookings/{bookingId}/status` — requires `bookings.manage`. Body: `toStatus`, `notes`, `cancellationReason`. Strictly enforces permitted lifecycle transitions and records audit event.

2. **Apple Calendar RFC 5545 iCalendar Sync Feed (`/calendar.ics`)**:
   - `GET /organizations/{org}/locations/{loc}/calendar.ics` — requires `bookings.read`. Returns `text/calendar; charset=utf-8` feed containing `VCALENDAR`/`VEVENT` components for scheduled appointments. Supports one-way subscription in macOS, iOS, iPadOS, Google Calendar, and Outlook.

3. **Invoicing & Payments API (`/invoices`)**:
   - `GET /organizations/{org}/locations/{loc}/invoices` — requires `invoices.read`. Returns invoices list with exact integer minor units (`subtotalCents`, `taxCents`, `totalCents`, `paidCents`, `dueCents`) and status.
   - `POST same /invoices` — requires `invoices.create`. Body: `customerId`, `bookingId`, `jobId`, `invoiceNumber`, `taxCents`, `notes`, `items` (array of `description`, `quantity`, `unitPriceCents`). Computes exact totals, validates customer, records initial `issued` status and event.
   - `GET same /invoices/{invoiceId}` — requires `invoices.read`. Returns invoice, itemized lines, payments history, and status audit events.
   - `POST same /invoices/{invoiceId}/payments` — requires `payments.record`. Body: `amountCents`, `method` ('cash', 'square_card', 'square_terminal', 'bank_transfer', 'cheque'), `providerReference`, `idempotencyKey`, `notes`. Enforces `CHECK(due_cents = total_cents - paid_cents)`, overpayment rejection, idempotency key uniqueness, auto-transitions to `partially_paid` or `paid`.
   - `POST same /invoices/{invoiceId}/void` — requires `invoices.manage`. Body: `notes`. Transitions status to `void`; blocked if recorded payments exist.

4. **SOP Compliance & Onboarding API (`/sops`)**:
   - `GET /organizations/{org}/locations/{loc}/sops` — requires `sop.read`. Returns active SOP documents with category, file name, SHA-256 fingerprint, version, page count.
   - `GET same /sops/acknowledgments` — requires `sop.read`. Optional `?employeeId=...` filter. Returns verified employee acknowledgment records.
   - `POST same /sops/{sopId}/acknowledge` — requires `sop.acknowledge`. Body: `trainingTrack` ('orientation', 'assisted', 'independent', 'certified'), `hash`, `notes`. Rejects hash mismatch against canonical document revision. Records non-repudiation log with timestamp and actor ID.

Customer portal source/native-tested contracts (schema26): GET /api/v1/portal/accounts and GET /api/v1/portal/accounts/{customer}/records require an active authenticated session plus explicit customer link. Records return customer/location display names, own equipment, booking summaries and non-draft invoice summaries, bounded100 per section; no private notes or provider references. POST /api/v1/portal/accounts/{customer}/vehicles accepts only description/categoryDescription/identifier and derives customer/scope from authorized link. No POST account enrollment endpoint. Staff permissions do not substitute for membership. Runtime/browser status is in latest checkpoint.

## Scoped quotations, immutable acceptance and atomic booking fulfillment — locally deployed schema 38, 2026-10-23
Migration 38 `scoped_quotations.sql` deployed after encrypted DPAPI backup, isolated restore table-count verification, and clean application restart.
Implements the full quotation lifecycle attached to scoped customer booking requests without modifying the immutable customer request snapshot:

### Staff Endpoints (under `/api/v1/organizations/{org}/locations/{loc}/quotes`):
- `GET /`: Requires `quotes.read`. Lists location quotations (up to 200).
- `POST /`: Requires `quotes.create`. Creates a new quotation draft. Subtotals are strictly computed on the server from line items in integer cents; caller-supplied subtotals/totals are not trusted. Body: `requestId`, `customerId`, `vehicleId`, `items` (description, quantity, unitPriceCents, optional serviceId), `taxCents`, `depositCents`, `internalNotes`, `customerNote`, optional `expiresAt`.
- `GET /{quote}`: Requires `quotes.read`. Returns complete quote details, items, event audit log, and acceptance record if accepted.
- `PUT /{quote}`: Requires `quotes.manage`. Optimistic draft updates requiring matching current `version`. Replaces line items atomically and increments version. Non-draft status returns 409 conflict.
- `POST /{quote}/issue`: Requires `quotes.issue`. Freezes draft quotation into `issued` status, captures `issuedAt` and `issuedBy` principal, increments version. Price amounts cannot be modified after issuance.
- `POST /{quote}/fulfill`: Requires `quotes.manage`, `bookings.create`, and `scheduling.reserve`. Atomically converts accepted quotation into confirmed capacity reservation and booking:
  - Validates quote is in `accepted` status and not expired.
  - Enforces deposit requirements (verified completed payment or explicit reviewed no-deposit configuration; fails closed if missing).
  - Locks resources in sorted order to avoid concurrent deadlocks.
  - Re-evaluates rule/capacity; capacity loss rolls back cleanly leaving quote intact in accepted status.
  - Links booking to quotation and updates quotation to `fulfilled`.
  - Records an immutable `quote_fulfillment_receipts` record, enforcing exactly one conversion receipt per request and per quotation at the DB level.

### Customer Portal Endpoints (under `/api/v1/portal/accounts/{customer}/quotes`):
- `GET /`: Requires authenticated session with explicit `customer_account_links` ownership. Returns customer's issued, accepted, and fulfilled quotations. Drafts and superseded revisions are suppressed.
- `GET /{quote}`: Requires customer ownership. Returns itemized quote details, line items, and terms.
- `POST /{quote}/accept`: Requires customer ownership. Accepts issued quote:
  - Validates `termsReviewed: true` and verifies quote is not expired.
  - Canonicalizes quote content and computes SHA-256 digest.
  - Atomically writes immutable `scoped_quotation_acceptances` record with actor ID, acceptance key, and content SHA-256 fingerprint.
  - Updates quote status to `accepted`.
  - Idempotent: identical actor/key retries return existing acceptance.
- `POST /{quote}/decline`: Requires customer ownership. Records customer decline note and transitions status to `declined`.
