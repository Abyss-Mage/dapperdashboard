## Decisions (user, 2026-11-11)
- **Serial number = both**: dealership invoices get their own number series (owner-set prefix, e.g. `DLR-0001`, separate from customer invoices), and each line can carry the car's VIN / stock number.
- **Due date**: each dealership invoice has a due date, editable, default 30 days after issue; "overdue" is a filter and prints on the PDF. This partly reverses the 2026-10-26 removal of "pay within" from dealerships (that removed it from the dealership record; the term now lives on each invoice). Tax stays the franchise's normal tax ("tax exempt" stays removed).
- **Client access**: the owner invites each dealership contact to a customer account (/account); they see all their invoices there and pay with Square. Every invoice email also has a "View and pay" button that opens the invoice after sign-in.

## What already exists (reuse, do not rebuild)
- `invoices` / `invoice_items` / `payments` / `invoice_events` with draft → issued → partially_paid / paid / void, one-per-booking rule only when booking_id is set (dealership invoices have none).
- Issuance with an issuer and numbering (`invoice_issuers`, quote prefix/next number beside it — the dealership series follows the same pattern).
- Printed templates per organization and per franchise (`printKind` in `print_template_kinds.go`: invoice and quotation); PDF generation (`invoice_pdf.go`).
- Emailing an issued quotation with an editable template (`quote_emails.go`, `email_templates.go`) — the pattern for the invoice email.
- Customer portal: invoices list, PDF, and **pay with Square** (`POST /api/v1/portal/accounts/{customer}/invoices/{invoice}/pay`, `account/InvoicePaymentForm.tsx`).
- Dealerships are customers (`dealership_accounts.customer_id`), with contacts and a per-car rate; customer-account linking for portal access exists (`customer-accounts` routes).

## Build plan
1. **Data** — migration: `invoices.dealership_account_id` (nullable), per-line `vin` and `stock_number` on `invoice_items`, dealership numbering (`dealer_prefix`, `dealer_next_number` on `invoice_issuers`), and `due_at` set on issue from a `terms_days` input (default 30). Overdue = issued/partially paid and `due_at < now()`.
2. **Editor (dashboard → Dealerships → Invoices)** — create a draft for a dealership: lines from the catalogue or free text, quantity, unit price (prefilled with the dealership's per-car rate), optional VIN / stock no. per line, notes, due-in days; save, issue (takes the next DLR number), void. Same shape as the quotation editor.
3. **Template + PDF** — a third print template kind "dealership invoice" (organization + optional franchise override, starting from the invoice template) with VIN / stock columns, due date and "overdue" stamp; the existing PDF code renders it.
4. **Email** — on issue, email the PDF to the dealership's primary contact (others optional) with an editable "Dealership invoice" email template and a "View and pay" link to `/account?invoice=…`. Resend button; delivery status recorded like quotes.
5. **Client dashboard** — in /account, a dealership contact sees an Invoices list (number, date, due, status, balance) with status and date filters, opens the PDF, and pays the balance with Square through the existing portal pay route. Paid invoices stay as history.
6. **Owner list, filters, ZIP** — Dealerships → Invoices list for all dealerships with filters (dealership, issue date range, status incl. overdue) and totals; "Download all as ZIP" builds the PDFs of the filtered set server-side (`archive/zip`, capped, e.g. 500 per download).
7. **Tests + deploy** — store tests (numbering, due date, VIN lines, overdue filter, portal ownership, pay updates status), HTTP tests (permissions: `invoices.*` + `dealership.read`), ZIP contents; deploy; mark #17 fixed.
